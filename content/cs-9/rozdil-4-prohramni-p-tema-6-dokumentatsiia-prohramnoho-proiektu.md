# Тема 6. Документація програмного проєкту (с. 122–125)

## 1. Що таке документація і для кого вона потрібна?

> 📌 **Документація програмного проєкту** — це набір текстових і графічних матеріалів, які описують мету, структуру, функціональність та правила використання програмного забезпечення.

Документація — не «баласт», а невід’ємна частина продукту: вона допомагає користувачам працювати з програмою, команді — узгоджувати дії, а тестувальникам — оцінювати якість (наприклад, за **чеклістами**).

## 2. Три рівні документування в Python-проєкті

### 1) Внутрішня (технічна) документація — на рівні коду (для розробників)
| Компонент | Де розташовується | Призначення |
| :--- | :--- | :--- |
| **Docstrings (`"""..."""`)** | Одразу після визначення модуля, класу, функції чи методу | Описує призначення, параметри, тип результату й винятки; доступна через `help()` |
| **Коментарі (`#`)** | Усередині складних блоків коду | Пояснює складну логіку та причини прийнятих рішень |
| **Анотації типів (Type hinting)** | У сигнатурах функцій: `def func(arg: str) -> bool:` | Статична перевірка типів і краща читабельність коду |
| **`requirements.txt`** | Кореневий каталог проєкту | Фіксує зовнішні залежності та їхні версії (`pip install -r`) |

### 2) Проєктна (структурна) документація — на рівні проєкту
| Документ | Зміст | Аудиторія |
| :--- | :--- | :--- |
| **`README.md`** | Назва, коротке призначення, швидка інсталяція, запуск, приклади | Усі користувачі та розробники |
| **`ARCHITECTURE.md`** | Детальний опис архітектури (модулі, пакети, бази даних, API) | Розробники, архітектори |
| **`CONTRIBUTING.md`** | Правила для співавторів (як вносити зміни, стандарти кодування) | Розробники, що долучаються |
| **`CHANGELOG / HISTORY`** | Хронологічний список змін, виправлень і нових функцій за версіями | Користувачі та розробники |

### 3) Зовнішня (користувацька) документація — на рівні споживача
- **Посібник користувача** — покрокові інструкції зі встановлення, налаштування та інтерфейсу простою нетехнічною мовою (приклад: опис мобільного застосунку *«Електронний щоденник»*).
- **API-референс** — автоматично згенерований опис класів і функцій із Docstrings.
- **FAQ та усунення несправностей** — відповіді на типові запитання (*«Що робити, якщо програма не запускається?»*).
