# Тема 2. Мікроконтролери, взаємодія з ними (с. 13–16)

## 1. Що таке мікроконтролер і з чого він складається?

> 📌 **Мікроконтролер** — це невеликий комп’ютер на одній платі, який може керувати різними пристроями.

Саме до плат мікроконтролерів підключають датчики та виконавчі механізми, щоб створювати розумні сигналізації, системи поливу, автоматичне освітлення, годування тварин тощо.

### Найпоширеніші плати
- **Arduino** — мікроконтролер із відкритим кодом, простий у використанні; програмується мовою, схожою на **C / C++**.
- **ESP32** — контролер із вбудованим **Wi-Fi** для підключення пристроїв до мережі.
- **Raspberry Pi** — повноцінний одноплатний комп’ютер для складніших IoT-проєктів; програмується мовами **Python, JavaScript** тощо.

### Основні компоненти типової плати
1. **Процесор** — виконує команди.
2. **Оперативна пам’ять (RAM)** — для тимчасового зберігання даних.
3. **Постійна пам’ять (Flash)** — для збереження програми.
4. **Порти вводу/виводу** — для підключення датчиків, світлодіодів, двигунів тощо.
5. **Інтерфейси зв’язку** — USB, Wi-Fi, Bluetooth, UART, I2C.

### Мови програмування плат
- **C / C++** — найчастіше для контролерів Arduino.
- **Python** — зручна для початківців, широко застосовується на Raspberry Pi.
- **JavaScript (через Node.js)** — для роботи з мережею та вебсервісами.
- **MicroPython або CircuitPython** — полегшені версії Python для мікроконтролерів.

## 2. Відкрита архітектура та відкритий код

> 📌 **Відкрита архітектура** — це принцип побудови комп’ютерних або електронних систем, за яким їх легко змінювати, розширювати та поєднувати з іншими пристроями чи програмами незалежно від виробника.

На відміну від відкритого ПЗ (наприклад, **LibreOffice**), **пропрієтарне** (закрите) програмне забезпечення не можна змінювати або копіювати без дозволу.

| Властивість | Відкрита архітектура | Закрита архітектура |
| :--- | :--- | :--- |
| **Можливості** | Запрограмовані правила можна змінювати й розширювати | Обмежена у можливостях |
| **Модулі** | Підтримує різні пристрої | Працює лише з «рідними» модулями |
| **Призначення** | Підходить для навчання та експериментів | Можна лише користуватися |
| **Розвиток** | Розвивається спільнотою (документація, сотні бібліотек і прикладів) | Контролюється одним виробником |

**Що означає відкритий код програми:**
- користувачі можуть вільно **запускати** програму з будь-якою метою;
- мають доступ **до вихідного коду** та можуть адаптувати його під свої потреби;
- можуть **вдосконалювати** програму та публікувати поліпшення для спільноти;
- можуть бути впевнені, що ПЗ не містить **прихованих функцій**, які загрожують конфіденційності чи безпеці.

## 3. API, сумісність та інтероперабельність

> 📌 **API (Application Programming Interface)** — це набір правил і команд, процедур, функцій, структур і констант, які уможливлюють взаємодію програм між собою або з обладнанням.

*Приклад із повсякденного життя:* мобільний застосунок погоди не зберігає дані про погоду самостійно — він звертається через **API** до метеорологічного сервера й отримує актуальні показники на екран.

> 📌 **Сумісність** — це здатність пристроїв або програм працювати разом без конфліктів (наприклад, флешка і ноутбук, PDF і смартфон).

> 📌 **Інтероперабельність** — ширший термін: здатність різних систем обмінюватися інформацією та використовувати її (наприклад, підключення принтера *Canon* до комп’ютера *Apple*, або взаємодія розумного холодильника й телевізора).

## 4. Прототип та етапи його створення

> 📌 **Прототип** — перша, спрощена версія майбутнього виробу (фізична на основі мікропроцесора або цифрова — інтерфейс сайту чи застосунку).

**Навіщо розробляють прототип:**
- перевірити функціональність (чи працює за задумом);
- оцінити зручність взаємодії користувача з продуктом;
- виявити технічні або логічні недоліки;
- прийняти рішення, що потрібно змінити, додати або прибрати.

### Етапи створення прототипу
1. **Формування ідеї** — розуміння, що саме має виконувати продукт.
2. **Планування структури** — визначення компонентів, вигляду та взаємодії з користувачем.
3. **Побудова первинної версії** — створення базового пристрою або програмної оболонки.
4. **Налагодження** — усунення початкових помилок і перевірка працездатності.

За результатами тестування виконують **модифікацію**: апаратної частини (заміна датчика, живлення), програмного коду (оптимізація, нові функції) або дизайну інтерфейсу.
