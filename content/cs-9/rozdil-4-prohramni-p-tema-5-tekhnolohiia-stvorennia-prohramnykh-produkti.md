# Тема 5. Технологія створення програмних продуктів (с. 114–121)

## 1. Програма vs Програмний продукт

> 📌 **Програма (Computer program)** — набір інструкцій мовою програмування, які комп’ютер виконує для вирішення конкретної задачі.

> 📌 **Програмний продукт (Software product)** — комплексне, цілісне рішення, створене для задоволення потреб користувача або бізнесу, яке має повний життєвий цикл (створення, підтримка, оновлення, розвиток).

**Чотири ключові елементи професійної розробки:**
1. **Чітка архітектура та модульність** — поділ на невеликі незалежні модулі з контрактами.
2. **Стандарти кодування та документація** — єдиний стиль (напр., **PEP 8** для Python) і вичерпна документація.
3. **Автоматизоване тестування** — юніт- та інтеграційні тести як «страховка» від регресій.
4. **Системи контролю версій** — наприклад, **Git**, для безпечної командної роботи та відстеження змін.

## 2. Планування, матриця пріоритетності та принцип Парето

> 📌 **Планування в програмуванні** — початковий етап розробки, де визначаються мета, вимоги, архітектура, послідовність дій, графік і терміни.

**4 етапи планування:** 1) Визначення мети → 2) Розбиття на маленькі завдання → 3) Визначення пріоритетів → 4) Оцінка часу.

### Матриця пріоритетності

| Важливість | Терміновість | Дії | Приклад |
| :---: | :---: | :--- | :--- |
| Висока | Терміново | **Робити відразу!** | Написати головну функцію програми |
| Висока | Не терміново | **Запланувати** на найближчий час | Написання документації |
| Низька | Терміново | **Делегувати або відкласти** | Дрібні правки в коді |
| Низька | Не терміново | **Можна не робити** | Додаткові прикраси інтерфейсу |

### Принцип Парето (правило 80/20)
> **20 % зусиль приносять 80 % результату** (і навпаки: 80 % зусиль можуть дати лише 20 % результату). Тому завжди починайте з головного функціоналу.

### 📖 Історична довідка
У **1896 році** італійський економіст **Вільфредо Парето** виявив, що 80 % землі та багатства в Італії належить 20 % населення. Пізніше **Джозеф Джуран** популяризував цей принцип як універсальний інструмент управління якістю.

## 3. Життєвий цикл і структура програмного проєкту

**6 основних етапів розробки ПЗ:**
1. **Планування та аналіз вимог**
2. **Проєктування та дизайн** (архітектура, UI/UX)
3. **Реалізація** (написання коду)
4. **Тестування** (юніт-, інтеграційні, системні тести)
5. **Впровадження** (розгортання)
6. **Супровід та підтримка**

> 💡 **Важливе правило:** що раніше знайдена помилка, то дешевше й легше її виправити.

### Модулі, пакети, `requirements.txt` і віртуальне середовище
- **Модуль** — будь-який файл `.py` (напр., `greetings.py`, `file_utils.py`, `math_operations.py`). Уникайте `from module import *`!
- **Пакет (Package)** — папка (напр., `my_package/`) зі спеціальним файлом `__init__.py` та модулями всередині:
  ```python
  from my_package.math_operations import add
  print(add(2, 5))  # 7
  ```
- **Типова структура проєкту:** папки `src/` (`main.py`, `greetings.py`), `tests/` (`test_greetings.py`), `docs/` (`README.md`) та файл `requirements.txt` (`pip freeze > requirements.txt`).
- **Віртуальне середовище (`venv`)** — ізольований простір із незалежними версіями пакетів для конкретного проєкту:
  - Windows: `venv\Scripts\activate`
  - macOS / Linux: `source venv/bin/activate`
