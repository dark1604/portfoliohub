# Тема 6. Координація роботи команди. Система контролю версій (с. 182–190)

## 1. Ролі в команді веброзробки
Над великими сайтами працює команда фахівців (попередньо плануючи **деревоподібну структуру** сайту):
- **Product-owner** — відповідає за бачення продукту, пріоритети й цінність для користувачів.
- **Дизайнер** — створює макети та UI/UX.
- **Верстальник (Front-end)** — перетворює макет на HTML/CSS/JS-код у браузері.
- **Програміст (Back-end)** — розробляє серверну логіку й бази даних.
- **Тестувальник (QA)** — перевіряє роботу сайту й шукає помилки.
- **Контент-менеджер** — наповнює сайт текстами, фото та відео.

## 2. Система контролю версій (СКВ / VCS), Git та GitHub
**СКВ** зберігає історію всіх змін коду в **репозиторії**, дає змогу повертатися до попередніх версій і працювати команді одночасно (бувають *локальні*, *централізовані* та *розподілені* — як **Git**).
**GitHub** (заснований у 2008 р.) — популярний вебсервіс для зберігання Git-репозиторіїв. Працювати можна в терміналі або через GUI-клієнти (*GitHub Desktop*, *VS Code*, *Sourcetree*, *GitKraken*).

### Базові команди Git:
- `git config --global user.name "Ім'я"` та `user.email "..."` — початкове налаштування.
- `git init` — створити локальний репозиторій; `git clone <url>` — скопіювати віддалений.
- `git add .` — додати зміни до індексу; `git commit -m "Опис"` — зафіксувати версію.
- `git branch` / `git checkout -b <гілка>` — створення та перемикання гілок; `git merge` — злиття гілок.
- `git pull origin master` — завантажити оновлення із сервера; `git push origin` — відправити свої коміти на сервер.

## 3. Методології керування проєктами: Scrum і Kanban
- **Scrum** — робота короткими фіксованими ітераціями (**спринтами**) у невеликих командах (до 10 осіб); популярні інструменти: *Jira*, *FlexiProject*.
- **Kanban** — візуальна дошка із завданнями-картками, які рухаються колонками (**To Do → Doing → Done**); популярний інструмент: *Trello*.
